# feedback.md

Archivo para reportar bugs, gaps o mejoras del **starter-template Mazelab** detectados desde este proyecto.

**Importante:** este archivo NO es para bugs/features del proyecto consumer. Es solo para findings sobre el starter mismo (skills faltantes, scripts rotos, anti-patrones en docs, contracts que no encajan en uso real).

## Cómo se usa

1. Cuando aldot ve algo del starter que falta o falla, le dice al agente del proyecto: _"anota esto en `feedback.md`"_.
2. El agente del proyecto agrega entry al final con fecha + descripción + contexto.
3. Cuando aldot vuelve a una sesión sobre el starter, le da al orquestador la ruta de este archivo. El orquestador lee, sintetiza al inbox global del starter, aplica fixes.

## Formato sugerido (flexible)

```
## YYYY-MM-DD — <título corto>
Contexto: qué estaba haciendo el proyecto cuando apareció el finding.
Finding: qué del starter falla / falta / molesta.
Acción sugerida (opcional): qué cambiar en el starter.
```

No hace falta seguir el formato al pie. Texto libre es OK si es claro.
